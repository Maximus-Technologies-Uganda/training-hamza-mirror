## 🔍 Technical Decisions

### Why GitHub Pages over Vercel?
**Chosen**: Static export to GitHub Pages

**Reasoning**:
1. **Cost**: Free for public repositories
2. **Simplicity**: No server infrastructure, just static files
3. **Learning**: Demonstrates understanding of static vs. SSR tradeoffs
4. **Portability**: Can migrate to any static host (Netlify, Cloudflare Pages)

**Tradeoffs Accepted**:
- No server-side rendering (SEO impact minimal for blog)
- No incremental static regeneration
- Client-side fetching only (initial page load not cached)
- Manual configuration of base paths for repository hosting

### Why WCAG 2.1 AA as Hard Requirement?
- Legal compliance in many jurisdictions
- Ethical responsibility to users with disabilities
- Automated testing catches ~40% of issues (axe-core, Lighthouse)
- Manual testing with keyboard and screen reader required
- CI pipeline blocks on violations

### Why Client-Side Fetching?
- Static export constraint (no server runtime)
- Simpler architecture (no hybrid rendering complexity)
- Acceptable for blog use case (not critical for SEO)
- Can add SSR later if requirements change
