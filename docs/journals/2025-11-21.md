## 7. What I Learned Today

1. **Documentation vs Implementation Gap**
   - Review packets can describe ideal state, not actual state
   - Always verify claims with code inspection and test runs
   - Documentation should be updated after implementation, not before

2. **Table-Driven Test Pattern**
   - Separate test data from test logic
   - Makes adding test cases trivial (just add row to table)
   - Self-documenting with description fields
   - Reduces duplication significantly

3. **run(argv) Architecture Pattern**
   - Pure functions are easier to test
   - Separate concerns: CLI logic vs process management
   - Module boundary pattern: only exit at entry point
   - Enables unit testing without spawning processes

4. **Infinity Policy Decision**
   - Technical decisions need rationale documented
   - Physical constraints (absolute zero) inform software design
   - Explicit rejection better than implicit failure
   - Tests should document the "why" not just the "what"

5. **Commit Message Best Practices**
   - Structure: Summary line + detailed body
   - Include metrics: test counts, coverage percentages
   - Explain what/why/impact
   - Reference issues/requirements closed
   - Professional tone without being verbose
