## Technical Highlights

### 1. Firebase Auth Integration
- **Client SDK**: Integrated Firebase Auth in Next.js frontend
- **Admin SDK**: Server-side token verification with Firebase Admin SDK
- **BFF Pattern**: Preserved browser → Next.js → API architecture (no direct API calls)
- **Session Management**: httpOnly session cookies (5-day expiry) for security

### 2. Authorization Model
- **Owner Role** (implicit): Users can manage their own posts
- **Admin Role** (explicit): Stored in Firebase custom claims, can manage any post
- **Middleware**: `requireOwnerOrAdmin()` for flexible authorization checks

### 3. Production Hardening

#### Zod Validation
- Migrated from JSON Schema to Zod for type-safe validation
- Better error messages and TypeScript integration
- Schemas: `createPostSchema`, `updatePostSchema`

#### CSRF Protection
- Double submit cookie pattern
- SameSite cookies with strict mode
- Token validation on all mutations (POST, PATCH, DELETE)

#### Rate Limiting
- Per-user mutation limits: 10 requests/minute
- Uses Firebase UID for authenticated users, IP for anonymous
- Proper 429 responses with Retry-After headers

### 4. Audit Logging
- Structured JSON logs via Pino
- All mutations logged: create, update, delete
- Metadata includes: userId, action, targetType, targetId, requestId
- Non-blocking: audit failures don't prevent mutations

### 5. Observability
- Request-ID propagation across all logs
- Health endpoints: `/health` (liveness), `/health/ready` (readiness)
- Firebase connectivity check in readiness probe
- Structured logging with audit filtering
