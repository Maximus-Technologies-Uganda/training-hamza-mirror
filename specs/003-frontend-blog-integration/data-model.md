# Data Model: Frontend Blog Integration

**Feature**: 003-frontend-blog-integration  
**Date**: November 27, 2025  
**Purpose**: Define TypeScript interfaces, validation rules, and state management for frontend entities

---

## Overview

The frontend data model mirrors the Blog Posts API entities, adding client-side validation, UI state management, and form handling concerns. All entities are TypeScript interfaces that ensure type safety throughout the application.

---

## Core Entities

### Post

**Description**: Represents a blog article retrieved from the API or submitted via forms. The Post entity is the primary data structure used throughout the application for displaying content and managing CRUD operations.

**TypeScript Interface**:

```typescript
/**
 * Blog post entity matching API response structure
 * Source: specs/002-blog-api/contracts/openapi.yaml
 */
export interface Post {
  /** Unique identifier (auto-generated by API) */
  id: number;
  
  /** Post title (1-200 characters, non-whitespace required) */
  title: string;
  
  /** URL-friendly slug (auto-generated by API from title) */
  slug: string;
  
  /** Post body content (1-50000 characters, non-whitespace required) */
  body: string;
  
  /** Creation timestamp in ISO 8601 format (immutable) */
  createdAt: string;
  
  /** Last update timestamp in ISO 8601 format */
  updatedAt: string;
}
```

**Field Constraints** (enforced client-side):

| Field | Type | Required | Min | Max | Pattern | Notes |
|-------|------|----------|-----|-----|---------|-------|
| id | number | Yes* | 1 | - | Positive integer | *Generated by API, not in forms |
| title | string | Yes | 1 | 200 | Non-whitespace | Trimmed before submission |
| slug | string | Yes* | - | - | Lowercase, hyphens | *Generated by API |
| body | string | Yes | 1 | 50000 | Non-whitespace | Trimmed before submission |
| createdAt | string | Yes* | - | - | ISO 8601 | *Set by API |
| updatedAt | string | Yes* | - | - | ISO 8601 | *Set by API |

**Validation Rules**:

```typescript
import { z } from 'zod';  // Optional: If using Zod for validation

// React Hook Form validation (recommended)
export const postValidationRules = {
  title: {
    required: 'Title is required',
    minLength: {
      value: 1,

      message: 'Title must be 200 characters or less'
    },
    validate: {
      notOnlyWhitespace: (value: string) => 
        value.trim().length > 0 || 'Title must contain non-whitespace characters'
    }
  },
  body: {
    required: 'Body content is required',
    minLength: {
      value: 1,
      message: 'Body must not be empty'
    },
    maxLength: {
      value: 50000,
      message: 'Body must be 50000 characters or less'
    },
    validate: {
      notOnlyWhitespace: (value: string) => 
        value.trim().length > 0 || 'Body must contain non-whitespace characters'
    }
  }
};
```

**State Transitions**:

```text
[Non-existent] 
    └─→ CREATE (POST /posts) → [Draft - Client]
            └─→ Submit → [Created - Server]
                    └─→ GET /posts/{id} → [Displayed]
                            ├─→ UPDATE (PATCH /posts/{id}) → [Updated]
                            │       └─→ Re-fetch → [Displayed with new data]
                            └─→ DELETE (DELETE /posts/{id}) → [Deleted]
                                    └─→ Removed from UI → [Non-existent]
```

**Usage in Application**:

```typescript
// Fetching posts
import useSWR from 'swr';
const { data: posts, error, isLoading } = useSWR<Post[]>('/api/posts', fetcher);

// Displaying post
<PostCard post={post} />

// Form submission
const createPost = async (data: CreatePostInput): Promise<Post> => {
  return fetchApi<Post>('/api/posts', {
    method: 'POST',
    body: JSON.stringify(data)
  });
};
```

### CreatePostInput

**Description**: Form data structure for creating new posts. Contains only user-editable fields (id, slug, timestamps are generated by API).

**TypeScript Interface**:

```typescript
/**
 * Input data for creating a new post
 * Sent to POST /posts endpoint
 */
export interface CreatePostInput {
  /** Post title (1-200 characters) */
  title: string;
  
  /** Post body content (1-50000 characters) */
  body: string;
}
```

**Validation**: Same rules as Post entity for title and body fields

**Example Usage**:

```typescript
import { useForm } from 'react-hook-form';

const CreatePostForm = () => {
  const { register, handleSubmit, formState: { errors } } = useForm<CreatePostInput>();
  
  const onSubmit = async (data: CreatePostInput) => {
    const newPost = await createPost(data);
    router.push(`/posts/${newPost.id}`);
  };
  
  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('title', postValidationRules.title)} />
      {errors.title && <span>{errors.title.message}</span>}
      
      <textarea {...register('body', postValidationRules.body)} />
      {errors.body && <span>{errors.body.message}</span>}
      
      <button type="submit">Publish</button>
    </form>
  );
};
```

### UpdatePostInput

**Description**: Form data structure for updating existing posts. All fields are optional (partial update). If field not provided, existing value remains unchanged.

**TypeScript Interface**:

```typescript
/**
 * Input data for updating an existing post
 * Sent to PATCH /posts/{id} endpoint
 * All fields optional - omitted fields retain existing values
 */
export interface UpdatePostInput {
  /** Updated post title (1-200 characters) */
  title?: string;
  
  /** Updated post body content (1-50000 characters) */
  body?: string;
}
```

**Validation**: Same rules as Post entity, but fields are optional

**Example Usage**:

```typescript
const EditPostForm = ({ post }: { post: Post }) => {
  const { register, handleSubmit } = useForm<UpdatePostInput>({
    defaultValues: {
      title: post.title,
      body: post.body
    }
  });
  
  const onSubmit = async (data: UpdatePostInput) => {
    const updated = await updatePost(post.id, data);
    router.push(`/posts/${updated.id}`);
  };
  
  // Form similar to CreatePostForm but with default values
};
```

### ApiError

**Description**: Standardized error response structure from the API. Used for displaying user-friendly error messages and handling different error scenarios.

**TypeScript Interface**:

```typescript
/**
 * Error response from Blog Posts API
 * Returned for 4xx and 5xx responses
 */
export interface ApiError {
  /** HTTP status code (400, 404, 429, 500, etc.) */
  statusCode: number;
  
  /** Error type/category (e.g., "Bad Request", "Not Found") */
  error: string;
  
  /** Human-readable error message */
  message: string;
}
```

**Error Scenarios**:

| Status Code | Error Type | Example Message | UI Handling |
|-------------|------------|-----------------|-------------|
| 400 | Bad Request | "title is required" | Show inline validation error |
| 404 | Not Found | "Post with id 123 not found" | Show 404 page or "Post not found" message |
| 429 | Too Many Requests | "Rate limit exceeded" | Show "Please wait and try again" with retry button |
| 500 | Internal Server Error | "An error occurred" | Show generic "Something went wrong" message |
| Network | Network Error | "Unable to reach server" | Show "Check connection" message with retry |

**Type Guard**:

```typescript
/**
 * Type guard to check if error is ApiError
 */
export function isApiError(error: unknown): error is ApiError {
  return (
    typeof error === 'object' &&
    error !== null &&
    'statusCode' in error &&
    'error' in error &&
    'message' in error
  );
}
```

**Usage in Error Handling**:

```typescript
const ErrorMessage = ({ error }: { error: unknown }) => {
  if (isApiError(error)) {
    return (
      <div role="alert" className="bg-red-50 border border-red-200 p-4">
        <h3 className="font-semibold text-red-800">
          {error.statusCode === 404 ? 'Not Found' : 'Error'}
        </h3>
        <p className="text-red-700">{error.message}</p>
        {error.statusCode === 429 && (
          <button onClick={retry}>Try Again</button>
        )}
      </div>
    );
  }
  
  // Fallback for unknown errors
  return <div role="alert">An unexpected error occurred</div>;
};
```

### HealthStatus

**Description**: API health check response indicating service availability. Used to display status indicator and inform error handling decisions.

**TypeScript Interface**:

```typescript
/**
 * Health check response from GET /health endpoint
 */
export interface HealthStatus {
  /** Status indicator: "ok" when healthy, "error" when unhealthy */
  status: 'ok' | 'error';
  
  /** Timestamp of health check in ISO 8601 format */
  timestamp: string;
}
```

**Usage**:

```typescript
import useSWR from 'swr';

export const useHealth = () => {
  const { data, error } = useSWR<HealthStatus>(
    `${API_URL}/health`,
    fetcher,
    {
      refreshInterval: 30000,  // Poll every 30 seconds
      revalidateOnFocus: false
    }
  );
  
  const isHealthy = !error && data?.status === 'ok';
  
  return { isHealthy, status: data, error };
};

// In component:
const HealthIndicator = () => {
  const { isHealthy } = useHealth();
  
  if (!isHealthy) {
    return (
      <div className="bg-yellow-50 border-l-4 border-yellow-400 p-4">
        <p className="text-yellow-700">
          API service is currently unavailable. Some features may not work.
        </p>
      </div>
    );
  }
  
  return null;  // No indicator when healthy
};
```

## Relationships

```text
Post (Core Entity)
  ├─→ CreatePostInput (subset: title, body only)
  ├─→ UpdatePostInput (partial: all fields optional)
  └─→ Displayed in:
      ├─→ PostList (array of Post)
      ├─→ PostCard (single Post preview)
      └─→ PostDetail (single Post full view)

ApiError (Error Handling)
  └─→ Displayed in:
      ├─→ ErrorMessage component
      ├─→ Form validation errors
      └─→ Error boundaries

HealthStatus (Service Status)
  └─→ Displayed in:
      └─→ HealthIndicator component (header/footer)
```
